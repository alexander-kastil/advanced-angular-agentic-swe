MCP works in both directions. The Angular CLI server lets an agent drive the workspace; WebMCP lets the running app expose its own tools to a browser agent. Angular 22 ships declareExperimentalWebMcpTool() and provideExperimentalWebMcpTools() in @angular/core, and provideExperimentalWebMcpForms() in @angular/forms/signals. This page really calls the first one, twice, in its constructor.

The application-wide alternative

declareExperimentalWebMcpTool ties a tool to the current injection context, so it unregisters when this component is destroyed. Use the provider form for tools that should live as long as the app or a lazy route.
