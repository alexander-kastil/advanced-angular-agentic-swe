Defer Non-Critical Views

A @defer block moves its dependencies into a separate chunk and downloads them only when the trigger fires. The placeholder is what the user sees until then, so the initial bundle shrinks without leaving a hole in the layout.

1. Trigger: on interaction

The chunk downloads the first time the placeholder is clicked or focused.

@defer (on interaction) { } @placeholder (minimum 300ms) { } @loading (minimum 200ms) {

Downloading the chart chunk...

} @error {

The chart chunk failed to load.

}

2. Trigger: on viewport

Scroll this block into view and the chunk starts downloading.

Keep scrolling
@defer (on viewport) { } @placeholder {
Not in the viewport yet
}

3. Trigger: when, with prefetch on idle

The chunk is prefetched while the browser is idle, then rendered the moment the condition turns true. The user pays no wait at all.

@defer (when armed(); prefetch on idle) { } @placeholder {
Waiting for the condition
}
  • Triggers: on idle, on viewport, on interaction, on hover, on timer, on immediate, when.
  • Any trigger can be paired with prefetch to separate downloading from rendering.
  • @placeholder content is part of the parent bundle, so keep it small.
  • minimum and after prevent a flash of placeholder on a fast connection.
  • Components used inside a defer block must not be referenced elsewhere in the same template, or the chunk is pulled back in eagerly.
