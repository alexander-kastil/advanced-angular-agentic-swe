Profile with Angular DevTools

Angular 22 ships enableProfiling() in @angular/core. It routes Angular's internal change detection events into the Chrome DevTools Performance panel, so a recording shows an Angular track next to Main, Interactions and Layout instead of an anonymous wall of frames. It is a development-mode feature and a no-op in a production build.

1. Turn the integration on

Development mode: {{ devMode ? 'yes' : 'no, this build is optimized and profiling is a no-op' }}

enableProfiling() returns the stop function. This component keeps it and calls it on destroy, which is the pattern to copy: leaving it on costs you every change detection pass for the rest of the session.

2. Record a trace, then generate a signature

Open DevTools, go to Performance, press record, click one of the buttons below, stop the recording. Each button wraps its work in performance.mark and performance.measure, so it also appears by name on the Timings track.

The measure covers the synchronous handler only. The render it schedules lands afterwards, which is exactly why you read the Angular track rather than trusting the number below.

  • The Angular DevTools extension has its own Profiler tab: it records change detection cycles and draws a bar chart per cycle plus a flame graph per component. Use it to find which component; use the Chrome Performance panel to find how long.
  • Record with the CPU throttled to 4x and the network to Fast 3G. An unthrottled desktop trace hides almost everything a user would feel.
  • Profile a production build served from dist/. A development build has no optimization, so its numbers are not the ones your users get.
  • Fix one thing per recording. Two changes in one trace and you cannot attribute the delta.
