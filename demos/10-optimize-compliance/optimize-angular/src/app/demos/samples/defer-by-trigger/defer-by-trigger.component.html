Every @defer Trigger, Side by Side

A trigger decides when a block renders. The chunk behind it is downloaded the first time any block needs it, so the second block that uses the same component renders with no network cost at all. The two tables below are measured live in your browser: the first from the components themselves, the second from PerformanceObserver on the resource timeline.

on immediate

Fires as soon as the surrounding template finishes rendering. Useful only to move code out of the initial bundle.

@defer (on immediate) { } @placeholder {
waiting
}

on idle

The default when no trigger is written. Waits for requestIdleCallback.

@defer (on idle) { } @placeholder {
waiting for idle time
}

on timer(3s)

A wall-clock delay. Honest but blunt: it fires whether the user cares or not.

@defer (on timer(3s)) { } @placeholder {
3 seconds after render
}

on hover

The pointer entering the placeholder is the signal. Nothing happens for keyboard-only users until they focus it.

@defer (on hover) { } @placeholder {
hover me
}

on interaction

Click or keydown on the placeholder. This is the one to pair with a real button.

@defer (on interaction) { } @placeholder { }

on viewport

An IntersectionObserver on the placeholder. The workhorse for anything below the fold.

scroll down
@defer (on viewport) { } @placeholder {
not in the viewport yet
}

when with prefetch on idle

The chunk is fetched during idle time, the block renders when the condition flips. The user waits for neither.

@defer (when armed(); prefetch on idle) { } @placeholder {
condition is false
}

  • The light panel has no dependencies, so its chunk is under a kilobyte. The heavy panel pulls moment in with a dynamic import(), so the first block that renders it fetches the whole library. That difference is the entire argument for deferring.
  • Two blocks share the heavy panel. Only the first one to fire pays for the download; the second renders from the module cache and adds no row at all.
  • Triggers compose: @defer (on viewport; on timer(5s)) fires on whichever comes first.
  • prefetch takes the same trigger grammar and separates downloading from rendering.
  • Never defer the LCP element. Deferring the thing the user came for makes the score worse.
  • In a production build the file names are hashed. Run ng build and read the lazy chunk table to see the same split before shipping.
