# Build Accessible UI

## Why this is now a legal requirement

The **European Accessibility Act** (Directive 2019/882) has applied since **28 June 2025**. Consumer
facing digital products and services placed on the EU market, including e-commerce, banking, ticketing
and e-books, must be accessible. The harmonised standard is **EN 301 549**, which for web content points
directly at **WCAG 2.2 level AA**.

Public sector bodies were already covered by the Web Accessibility Directive. The EAA extends the same
bar to private companies, with market surveillance and penalties per member state.

## What WCAG 2.2 added over 2.1

| Criterion | Level | Requirement |
| --- | --- | --- |
| 2.4.11 Focus Not Obscured (Minimum) | AA | The focused element must not be entirely hidden by sticky headers or overlays |
| 2.5.7 Dragging Movements | AA | Every drag interaction needs a single-pointer alternative |
| 2.5.8 Target Size (Minimum) | AA | Pointer targets are at least 24 by 24 CSS pixels, or spaced apart |
| 3.2.6 Consistent Help | A | Help mechanisms appear in the same relative order on every page |
| 3.3.7 Redundant Entry | A | Information already entered is auto-filled or offered for selection |
| 3.3.8 Accessible Authentication (Minimum) | AA | No cognitive function test without an alternative |

4.1.1 Parsing was removed. Sticky toolbars, drag-and-drop lists and 20-pixel icon buttons are the three
things most Angular apps fail on.

## @angular/aria

`@angular/aria` ships headless behaviour primitives: the roles, the ARIA wiring, the roving `tabindex`,
the typeahead and the keyboard model, with no styling opinion at all.

```bash
npm install @angular/aria
```

```html
<div ngTabs>
  <ul ngTabList [(selectedTab)]="selectedTab">
    <li ngTab value="criteria">WCAG 2.2 AA</li>
    <li ngTab value="widgets">Aria widgets</li>
  </ul>

  <div ngTabPanel value="criteria">
    <ng-template ngTabContent>...</ng-template>
  </div>
</div>
```

The `ng-template[ngTabContent]` wrapper makes the panel content lazy: it is created the first time its
tab is selected. Hidden panels get the `inert` attribute, so they leave the accessibility tree instead
of being read out by a screen reader.

Available primitives: `accordion`, `combobox`, `grid`, `listbox`, `menu`, `tabs`, `toolbar`, `tree`.
Each has a matching `/testing` entry point with harnesses.

`@angular/aria` gives you behaviour. It does not give you contrast, focus indicators, target size or
meaningful text. Those are still yours.

## Lint the templates

Static analysis catches most of the ARIA defects before review.

```javascript
// eslint.config.js
{
  files: ['**/*.html'],
  extends: [angularTemplate.configs.recommended, angularTemplate.configs.accessibility],
  rules: {
    '@angular-eslint/template/alt-text': 'error',
    '@angular-eslint/template/elements-content': 'error',
    '@angular-eslint/template/label-has-associated-control': 'error',
    '@angular-eslint/template/table-scope': 'error',
    '@angular-eslint/template/valid-aria': 'error',
    '@angular-eslint/template/click-events-have-key-events': 'error',
    '@angular-eslint/template/interactive-supports-focus': 'error',
    '@angular-eslint/template/no-autofocus': 'error',
    '@angular-eslint/template/button-has-type': 'error'
  }
}
```

Run it in CI:

```bash
npm run lint
```

## Audit with axe

`axe-core` checks the rendered DOM, which is where the real defects live.

```typescript
const axe = await import('axe-core');
const result = await axe.default.run(element, {
  runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa', 'wcag21aa', 'wcag22aa'] }
});
```

The dynamic `import()` keeps axe out of the initial bundle. In CI, run the same rule set through
`@axe-core/playwright` against real pages.

Automated tools find roughly a third of the defects. The rest need a keyboard and a screen reader:

1. Unplug the mouse and reach every control with Tab, Shift+Tab, arrows, Enter, Space and Escape.
2. Check that the focus ring is always visible and never covered.
3. Read the page with NVDA, JAWS or VoiceOver and listen to what a control announces.
4. Zoom to 200 percent and reflow at 320 CSS pixels wide.

## Angular specifics

- Give every route a `title`. The Router announces it on navigation.
- Use `LiveAnnouncer` from `@angular/cdk/a11y` for state that changes without a navigation.
- Use `cdkTrapFocus` for dialogs and drawers.
- Semantic elements first: a `button` is not a `div` with a click handler, whatever the ARIA says.
